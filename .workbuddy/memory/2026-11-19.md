## 修复：cloud-agent 迁移前需卸载 cloud-init 挂载光盘

- 文件：`cloud-agent/src/main/java/cn/ruiyun/cloud/agent/operate/impl/GuestOperate.java`
- 问题：`migrate` 方法直接调用 `domain.migrate(...)`，cloud-init ISO 是宿主机本地文件（默认 `/var/kvm-cloud/{虚拟机名}.iso`），作为 CD-ROM 随域迁移到目标主机后因文件不存在导致迁移失败。
- 方案：在 `domain.migrate(...)` 前新增 `detachCloudInitCdRom(domain, domainXml)`，从 domain XML 中定位 cloud-init 光盘（metadata 中 `kvm-cloud:fileinfo` 且 `cleanup-flag=yes` 的 resource-path，或 `target dev='hdb'`；普通光驱为 `hda`），去掉 `<source>` 后调用 `domain.updateDeviceFlags(xml, 1)` 弹出光盘。
- **重要修正**：迁移带 `VIR_MIGRATE_UNDEFINE_SOURCE`，成功后源端 domain 已被 undefine，后续 `stopDomain` 会立即跳出且 `xml` 为 null，`cleanVmResource` 根本不会执行，ISO 会残留。故改为：迁移前 `String domainXml = domain.getXMLDesc(0)` 保存，迁移成功后显式 `cleanVmResource(domainXml)` 删除源端 cloud-init ISO 及 channel 文件。DOM4j 对传入 XML 的内存修改不影响原始 String，清理逻辑可正常读到 metadata 的 fileinfo。

### 关键上下文（复用）
- cloud-init CD-ROM 模板：`tpl/kvm/vm/cd/local/cloud.xml.json`，`target dev=hdb`、`address unit=1`、`source file=/var/kvm-cloud/{name}.iso`；普通光驱为 `hda`/`unit=0`。
- 卸载光盘既有范式：`detachCdRoom`/`attachCdRoom` 传不含 `<source>` 的 XML 给 `updateDeviceFlags(xml, 1)`。
- 迁移调用链：`GuestController.migrate` -> `GuestService.migrate` -> `MigrateGuestOperateServiceImpl.operate` -> agent `GuestOperate.migrate`。
